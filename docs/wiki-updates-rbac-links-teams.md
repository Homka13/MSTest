# Оновлення LMS Upload Portal: Ролі доступу Entra ID, Перевірка ресурсів та Сповіщення Teams

[[_TOC_]]

## 1. Загальний огляд оновлення

Це оновлення вирішує три ключові операційні та безпекові задачі порталу приймання навчальних матеріалів:

1. **Розмежування доступу (RBAC):** зовнішні користувачі (тренери брендів та дистриб'юторів, що входять через Entra External ID / CIAM Email OTP) більше не мають доступу до внутрішньої черги модерації та системних довідників. Вони бачать лише інструменти самообслуговування для завантаження матеріалів.
2. **Перевірка доступу до зовнішніх ресурсів:** автоматична перевірка доступності посилань на Google Drive, YouTube, розгортання захисних посилань Proofpoint та маркування корпоративних мережевих UNC-шляхів зі статусом `PendingAccess`.
3. **Сповіщення в Microsoft Teams:** оперативна доставка повідомлень відповідальним модераторам через Incoming Webhook / Power Automate з кнопками швидкої дії та повною інформацією про матеріал.
4. **Розділення полів тренера та імпортера:** явне відокремлення конкретного автора/тренера від компанії-імпортера/дистриб'ютора як у формі подання, так і в картці модератора.

## 2. Рольова модель доступу (Microsoft Entra ID RBAC)

### 2.1. Архітектурна концепція

Портал використовує корпоративні **App Roles** Microsoft Entra ID. Авторизація працює на рівні стандартного системного клейму `roles` в ID-токені MSAL.

::: mermaid
graph TD
    User([Користувач порталу]) --> MSAL[MSAL Browser: Login Redirect]
    MSAL --> Entra[Microsoft Entra External ID CIAM]
    Entra --> Token[ID Token з клеймами]
    Token --> AppRoles{Перевірка idTokenClaims.roles}
    AppRoles -- "Містить 'Admin' або 'LMS.Admin'" --> AdminRole[Роль: 👑 Адміністратор]
    AppRoles -- "Без ролі / інші користувачі" --> TrainerRole[Роль: 🎓 Тренер]
    
    AdminRole --> AccessAll[Повний доступ:<br/>• Додати матеріал<br/>• Парсер тестів<br/>• Черга на перевірці<br/>• Довідники]
    TrainerRole --> AccessLimited[Обмежений доступ:<br/>• Додати матеріал<br/>• Парсер тестів]
:::

### 2.2. Матриця прав доступу

| Розділ порталу | Вкладка | Роль: Тренер (`trainer`) | Роль: Адміністратор (`admin`) |
|---|---|:---:|:---:|
| Форма подання матеріалу | `form` | ✅ Повний доступ | ✅ Повний доступ |
| Парсер тестів (.txt) | `test_parser` | ✅ Повний доступ | ✅ Повний доступ |
| Черга на перевірці | `queue` | ❌ Приховано (захист + редірект) | ✅ Повний доступ (валідація, статус доступу, правка метаданих) |
| Системні довідники | `settings` | ❌ Приховано (захист + редірект) | ✅ Повний доступ (бренди, типи, хеші, Teams) |

### 2.3. Захист інтерфейсу в клієнтському додатку

- **Навігаційні меню:** вкладки `queue` та `settings` повністю виключені з рендерингу в десктопному хедері та мобільному меню для користувачів без ролі `Admin`.
- **Автоматичний редірект:** якщо користувач з роллю `trainer` вручну перемикає вкладку або має збережений стан, `useEffect` автоматично переводить його на вкладку `form`.
- **Екран блокування (Defense-in-depth):** у разі прямого потрапляння на адмінські вкладки відображається інформаційний щит обмеження доступу (`ShieldAlert`).
- **Візуальний статус:** у шапці профілю та на зеленому бейджі автентифікації Entra ID чітко вказано поточну роль користувача: `👑 Адміністратор` або `🎓 Тренер`.

### 2.4. Інструкція з налаштування в Microsoft Entra ID (Azure Portal)

Для надання користувачам ролі адміністратора виконуються наступні дії:

#### Крок 1. Створення App Role в App Registration
1. Увійти в **Azure Portal** або **Entra admin center** у тенант `KnowlageUploadPortal`.
2. Перейти в **App registrations** ➔ обрати застосунок `KnowlageUploadPortal OTP` (Client ID: `483ad8a5-ad99-460c-8a4e-de7cf724b494`).
3. Відкрити пункт **App roles** (або відредагувати **Manifest**) та додати роль:
```json
{
  "allowedMemberTypes": ["User"],
  "description": "Адміністратори LMS Upload Portal (повний доступ до черги та налаштувань)",
  "displayName": "LMS Admin",
  "id": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "isEnabled": true,
  "value": "Admin"
}
```
*(Значення атрибута `value` має бути обов'язково `"Admin"`).*

#### Крок 2. Призначення ролі адміністраторам
1. Перейти в **Enterprise applications** ➔ знайти `KnowlageUploadPortal OTP`.
2. Відкрити розділ **Users and groups** ➔ **Add user/group**.
3. Обрати співробітників, які відповідають за модерацію та налаштування, і призначити роль **LMS Admin**.
4. Усі зовнішні користувачі (тренери, представники брендів), які реєструються за Email OTP самостійно, не мають цієї ролі і автоматично отримують права `trainer`.

#### Крок 3. Резервний локальний конфіг (для тестування)
Для локальної розробки у файлі `.env` підтримується список поштових скриньок адміністраторів:
```bash
VITE_ADMIN_EMAILS=moderator@company.com,lead-trainer@company.com
```

## 3. Розділення полів «Тренер» та «Імпортер / Бренд-дистриб'ютор»

### 3.1. Обґрунтування

Раніше у системі було присутнє лише одне комбіноване поле. На практиці:
- **Тренер** — це конкретна фізична особа (автор/спікер), ім'я якої автоматично підтягується з облікового запису Entra ID (`account.name` або `account.username`).
- **Імпортер / Бренд-дистриб'ютор** — це юридична особа або компанія-дистриб'ютор (наприклад, дистриб'ютор побутової чи цифрової техніки), якій належить продуктова лінійка.

### 3.2. Реалізація

- **Форма завантаження (`MaterialUploadForm.tsx`):**
  - Поле **«Тренер / Автор тренінгу»**: за замовчуванням заповнюється іменем поточного залогованого користувача. Дозволяє ручне редагування за потреби.
  - Поле **«Імпортер / Бренд-дистриб'ютор»**: обов'язкове текстове поле, оснащене автодоповненням `<datalist>` на основі довідника брендів порталу. За замовчуванням порожнє.
- **Черга модератора (`VerificationQueue.tsx`):**
  - Окреме відображення автора та імпортера у списку матеріалів.
  - Обидва поля доступні для перевірки та коригування модератором у модальному вікні редагування метаданих.

## 4. Перевірка доступу до зовнішніх ресурсів (External Links Verifier)

### 4.1. Проблематика

Матеріали часто надсилаються у вигляді посилань на хмарні диски чи мережеві сховища. Виникають типові помилки:
1. Посилання «загорнуті» у корпоративний фільтр **Proofpoint URL Defense**, що спотворює оригінальну адресу.
2. Файли на **Google Drive** розшарені лише «для окремих користувачів» або «для організації тренера», а не для модераторів компанії.
3. Посилання вказують на локальні Windows UNC-шляхи (`\\fileserver\share\...`), недоступні з публічного інтернету.

### 4.2. Алгоритм роботи сервісу (`src/services/linkVerifier.ts`)

::: mermaid
flowchart TD
    In[Вхідне посилання] --> Proofpoint{Це Proofpoint urldefense?}
    Proofpoint -- Так --> Unwrap[Розгортання оригінального URL з параметру u=]
    Proofpoint -- Ні --> DetectType[Визначення типу ресурсу]
    Unwrap --> DetectType

    DetectType -->|Google Drive| DriveCheck[Перевірка ID файлу через публічне прев'ю]
    DetectType -->|YouTube| YTCheck[Запит до YouTube oEmbed API]
    DetectType -->|UNC шлях \\server\share| UNCCheck[Позначення типу 'unc_network']
    DetectType -->|Звичайний Web URL| WebCheck[Валідація структури URL]

    DriveCheck -->|Прев'ю відкривається| P1[Статус: Доступ публічний ✅]
    DriveCheck -->|Помилка завантаження| P2[Статус: Доступ обмежено ⚠️ -> PendingAccess]

    YTCheck -->|200 OK| Y1[Статус: Відео доступне ✅]
    YTCheck -->|404 Not Found| Y2[Статус: Відео недоступне або приватне ⚠️]

    UNCCheck --> U1[Статус: Локальний мережевий ресурс ⚠️ -> PendingAccess]
:::

### 4.3. Інтерфейсна взаємодія

1. **У формі подання (`MaterialUploadForm`):**
   - Кнопка **«🔍 Перевірити доступ»**: запускає експрес-діагностику введеного посилання.
   - Кнопка **«🔗 Відкрити»**: відкриває очищене розгорнуте посилання в новій вкладці для швидкої ручної перевірки.
   - Кольоровий статусний бейдж попереджає тренера, якщо посилання має закритий доступ.
2. **У черзі модератора (`VerificationQueue`):**
   - Матеріали зі статусом `PendingAccess` позначаються бурштиновим банером: *«Потрібно підтвердити доступ до зовнішнього ресурсу»*.
   - Кнопка **«🔗 Перевірити ресурс»**: дозволяє модератору в один клік відкрити посилання.
   - Кнопка **«✅ Доступ підтверджено»**: автоматично переводить матеріал зі статусу `PendingAccess` у звичайний робочий статус `UnderReview` для подальшої обробки.

## 5. Сповіщення в Microsoft Teams

### 5.1. Призначення

Забезпечення проактивного інформування модераторів та методистів про кожен новий матеріал через корпоративний канал або групу Microsoft Teams без необхідності тримати портал постійно відкритим.

### 5.2. Архітектура та формат повідомлення

Повідомлення відправляються через **Microsoft Teams Incoming Webhook** (або сумісний тригер Power Automate Workflows).

Формат повідомлення базується на стандарті **Office 365 Connector Card (MessageCard)**:
- **Заголовок:** індикатор статусу та назва продукту.
- **Секція фактів:**
  - Бренд / Дистриб'ютор
  - Тренер / Автор
  - Тип матеріалу та мова
  - Дата проведення навчання
  - Статус доступності зовнішнього посилання
- **Потенційні дії (PotentialAction):**
  - Кнопка «Відкрити в порталі» (пряме посилання на чергу модератора).
  - Кнопка «Перейти до ресурсу» (посилання на Google Drive / YouTube / матеріали).

::: mermaid
sequenceDiagram
    autonumber
    actor Trainer as 🎓 Тренер
    participant Form as Форма порталу
    participant Verifier as Сервіс LinkVerifier
    participant TeamsService as Сервіс TeamsNotifier
    participant Webhook as Microsoft Teams Webhook
    actor Admin as 👑 Модератор LMS

    Trainer->>Form: Заповнює форму та додає посилання
    Form->>Verifier: Перевірка доступності посилання
    Verifier-->>Form: Результат (OK або PendingAccess)
    Trainer->>Form: Натискає «Подати матеріал»
    Form->>TeamsService: sendMaterialNotification(material, config)
    TeamsService->>Webhook: POST MessageCard JSON (CORS/no-cors fallback)
    Webhook-->>Admin: Спливаюче сповіщення в каналі Teams
    Admin->>Form: Перехід за кнопкою з картки для модерації
:::

### 5.3. Налаштування в розділі «Довідники»

У вкладці **«Довідники»** адміністраторам доступний новий блок налаштувань **«Сповіщення Microsoft Teams»**:
- **Перемикач активності:** швидке увімкнення та вимкнення сповіщень.
- **Webhook URL:** захищене поле для адреси вебхука Microsoft Teams.
- **Фільтр перевірки доступу:** опція *«Надсилати сповіщення лише якщо матеріал потребує перевірки доступу (PendingAccess)»*.
- **Кнопка тестування:** *«🧪 Надіслати тестове сповіщення»* для миттєвої перевірки правильності Webhook URL без створення фіктивних матеріалів.
